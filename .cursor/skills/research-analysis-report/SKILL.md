# 연구 및 분석 결과 작성

## 핵심 원칙

1. 최대한 핵심만 직관적이지만 이해하기 쉽게
2. 실제 데이터 지표와 로직을 토대로 설명
3. 의도랑 목적, 결과등이 뚜렷함

관측값과 해석을 분리한다. 실행하지 않은 로직, 확인하지 않은 수치, 로그에 없는 원인은 추측해서 작성하지 않는다.

## 작업 순서

1. 분석 대상 문서와 실제 구현 코드를 함께 읽는다.
2. 로직에서 입력값, 조건, 대조군, 성공 기준을 찾는다.
3. 가능하면 로직을 실행하고 명령, 환경, 원본 지표를 확보한다.
4. 기대값과 실측값을 비교하여 완료 조건 충족 여부를 판단한다.
5. 아래 형식으로 핵심 결과만 작성한다.

## 작성 형식

### 목적

무엇을 확인하려는 실험인지 한두 문장으로 설명한다.

### 조건

- 사용한 코드 경로와 실행 명령
- 입력값, 대기 시간, 용량처럼 결과에 영향을 주는 값
- 실험군과 대조군

### 결과

실제 로그나 지표를 필요한 범위만 인용한다. 단위와 측정 대상을 반드시 적는다.

### 분석

- 수치가 의미하는 동작을 실제 코드 경로와 연결한다.
- 기대 범위와 실측값의 차이를 설명한다.
- 성공 조건을 충족했는지 명확히 결론 낸다.
- 런타임 내부 이벤트, 스케줄링 편차처럼 해석에서 제외한 항목과 이유를 적는다.

## 작성 기준

- 결론을 먼저 제시하고 근거를 뒤에 둔다.
- 로직의 함수명, 분기, 입력값과 결과 지표를 직접 연결한다.
- 여러 dump는 비교에 필요한 이벤트만 하나로 합쳐 보여준다.
- 시간은 원 단위와 읽기 쉬운 환산값을 함께 쓴다. 예: `51049333ns`, 약 `51.05ms`.
- 예상 결과는 예상이라고 표시하고 실측 결과처럼 쓰지 않는다.
- 재현하지 못했거나 명세가 불명확하면 확인이 필요하다고 명시한다.
- 같은 설명을 코드, 로그, 본문에서 반복하지 않는다.
