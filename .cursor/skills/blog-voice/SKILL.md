# 블로그 말투

이 스킬은 문장 말투만 담당한다. 프런트매터, H1 금지, series, Hugo 빌드는 저장소 루트 `AGENTS.md`를 따른다. 실험 결과 양식(목적, 조건, 결과, 분석)은 `research-analysis-report` 스킬이 담당한다. 두 스킬은 겹쳐 쓸 수 있다.

글을 쓰기 전에 [examples.md](examples.md)를 읽고, 그 리듬을 따른다.

## 말투

- 1인칭 경험으로 쓴다. "진행해봅시다", "적용해봤습니다", "놀랐던 적이 있습니다". 백과사전처럼 3인칭 정의로 시작하지 않는다.
- 설명은 `합니다`/`입니다`로 이어가고, 구간을 닫을 때 `죠`/`더군요`/`네요`를 섞는다. 모든 문장을 `죠`로 끝내지 않는다.
- 정의 나열이 아니라 상황으로 연다. 비용, 장애, 이전 글, 의문처럼 실제 계기를 먼저 두고 그다음에 원리로 들어간다.
- 추론 흐름을 드러낸다. 처음에는 X, 그래서 Y를 시도, 결과는 Z. 결론만 던지지 않는다.
- 용어는 처음 나올 때 한 줄로 정의한다. 예: `VAD(음성 활동 검출, 말 있는 구간을 찾는 기법)`. `SSE는 Server-Sent Events이고, HTTP 응답을 닫지 않은 채 서버가 이벤트를 계속 밀어 넣는 방식입니다.`
- 수치에는 단위와 전후를 같이 쓴다. 실행하지 않은 값, 로그에 없는 원인은 추측하지 않고 "확인이 필요합니다"라고 적는다.
- 이전 글은 내부 링크로 잇고, "위에서 언급한", "해당 글에서 다룰"처럼 글 안의 위치를 가리킨다.
- 문법적으로 완결된 문장을 쓴다. 전보식 축약, 볼드/이모지 남용, 가운뎃점, 인사치레는 쓰지 않는다.
- HLS에서 ABR은 Adaptive Bitrate이다. 세그먼트를 가져오는 주체는 클라이언트/플레이어이지 서버가 아니다.

## 하지 말 것

- "정리하면 다음과 같습니다. 핵심은 세 가지입니다."처럼 일반 LLM 요약체로 열지 않는다.
- 글을 교과서 목차처럼 개념부터 쌓지 않는다.
- 확인하지 않은 수치나 원인을 단정하지 않는다.
