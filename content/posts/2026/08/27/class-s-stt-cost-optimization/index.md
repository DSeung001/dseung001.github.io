# 개요


기존에는 강의를 업로드할 때 대략 $1.2~$1.5 선으로 나왔죠. <br/>
이는 서버 비용이 아닌 AI 비용으로 하루에 4~5시간짜리 영상을 올리면 여기서 텍스트를 추출하고 임베딩하는 비용을 나타냅니다.

`Whisper`를 사용했는데 이는 제출한 오디오 길이에 비례해 과금되는 방식입니다.<br/>
OpenAI `whisper-1`은 분당 $0.006이고 4시간이면 아래와 같이 
> 240분 x $0.006 = $1.44

대략 비슷하게 나온 걸 알 수 있는데, 생각보다 `Whisper` 모델을 GPT API로 쓰니 금액이 부담스러웠고 이는 최적화가 가능해보였습니다.


# 해결 과정

STT 비용을 줄이려면 Whisper에 넣는 오디오 길이를 줄이거나, 같은 모델을 더 싼 API로 바꾸면 됩니다. <BR/>
Class S는 두 가지를 같이 적용해봤습니다.

```mermaid

```

## 무음 처리

Whisper는 말이 없는 침묵 구간도 오디오 길이에 포함해 과금합니다. 그래서 먼저 영상에서 무음을 빼고, 말 있는 부분만 Whisper에 넣는 방법부터 시도했습니다.

5분짜리 강의 샘플로 실험해 보니, 무음을 잘라 말 구간만 이어 붙이면 길이가 약 300초에서 272초로, 대략 10% 줄었습니다. 원본의 절반 가까이가 침묵이었는데 그 비중이 낮아지면서 말이 더 촘촘하게 들어갔고, 전사 결과는 오히려 더 안정적으로 느껴졌습니다.

다만 이건 소리를 키워서 좋아진 게 아닙니다. 처리 후 평균 음량은 원본보다 조금 더 작았고, 무음을 줄여 말 구간 비중이 높아진 영향에 가깝습니다.

Class S에도 같은 방식을 적용했습니다. 흐름은 아래와 같습니다.

1. 영상 음량을 먼저 측정합니다.
2. 강의마다 녹음 레벨이 달라 고정 dB 하나로 자르지 않고, 그 영상의 음량에 맞춰 무음 기준을 잡습니다.
3. 무음 구간을 찾아 말 있는 부분만 이어 붙인 뒤 Whisper에 보냅니다.
4. Whisper가 돌려준 자막 시간은 원본 영상 시간으로 되돌립니다. 검색이나 하이라이트는 원본 재생 위치를 써야 하기 때문입니다.

## 배속 적용

Whisper는 결국 제출 오디오 길이에 비례해서 금액을 책정하더군요. 그러면 어느 정도 배속을 해도 괜찮지 않을까 하는 접근이 있었습니다.

같은 5분 샘플로 배속까지 올려 비교했습니다.

| 케이스 | 길이 | 원본 대비 감소 | 판단 |
|---|---:|---:|---|
| 원본 | 299.94초 | 기준 | 품질 기준선 |
| 압축 | 272.01초 | 약 9.3% | 절감폭이 작음 |
| 압축 + 1.25배속 | 217.62초 | 약 27.4% | 비용/품질 균형 |
| 압축 + 1.5배속 | 181.34초 | 약 39.5% | 품질 저하로 비추천 |

품질 판단은 당시 로컬 테스트 모델 기준입니다. 절대적인 전사 정확도보다, 배속을 올렸을 때 얼마나 더 망가지는지를 비교하는 데 초점을 뒀습니다. 테스트 모델 성능이 좋지 않아 전반적으로 이상한 표현이 많이 나왔지만, 1.25배속과 1.5배속 사이 차이는 충분히 구분됐습니다.

| 관점 | 1.25배속 | 1.5배속 |
|---|---|---|
| 강의 흐름 | 문장 단위로 따라갈 수 있음 | 큰 흐름은 비슷 |
| 핵심 단어 | 일부만 틀림 | 핵심 단어가 자주 깨짐 |
| 반복 출력 | 거의 없음 | 같은 말이 연속 반복 |
| 길이 절감 | 약 27% | 약 40% |

1.25배속은 가끔 단어 하나가 틀려도 강의 내용을 따라가는 데 무리가 없었습니다. 1.5배속은 비용은 더 줄지만 핵심 단어가 더 자주 깨지고, 끝부분에 같은 말이 반복되는 환각이 붙었습니다. 자동 자막 파이프라인에서는 이런 반복을 따로 걸러야 해서 운영 부담이 커집니다. 그래서 대량 처리 기본값은 1.25배속으로 두었습니다.

무음 제거가 성공한 경우에만 1.25배속을 적용하고, 자막 시간은 원본 영상 시간으로 되돌립니다.

## Groq 적용

Groq는 Whisper 계열 모델을 자체 하드웨어로 제공하는 STT API입니다. 검증 단계를 줄이고 해당 작업에 특화된 하드웨어로 돌리더군요. Class S는 교사 BYOK(Bring Your Own Key)로 OpenAI 또는 Groq를 고르고, STT는 `whisper-large-v3-turbo`를 씁니다.

단가를 비교하면 Groq turbo가 OpenAI `whisper-1`보다 훨씬 쌌습니다. 같은 길이라면 단가가 약 9분의 1입니다. 과금 기준은 원본 영상 길이가 아니라 Whisper에 실제로 제출한 chunk 길이입니다. VAD, 배속, 하드컷 overlap이 이 길이를 바꿉니다.

금액을 알아보니 기본적으로도 Whisper 대비해서 쌌지만, 개발자 플랜이 현재 막혀 있다는 소식을 보게 되었죠. 사이트에서 업그레이드를 막아 둔 경우는 처음 봤습니다.

# 적용

현재는 무음 처리 + 1.25배속 + Groq를 적용해서, 추정치 기준 하루 약 $1.48에서 $0.11로 많이 줄일 수 있었습니다.

![usage](./image/usage.webp)

절감의 대부분은 단가 인하입니다. VAD와 1.25배속은 그 위에서 Whisper에 제출하는 오디오 길이를 약 27% 더 줄입니다.

STT 모델 단가는 아래와 같습니다.

| Provider | 모델 | 단가 | 분당 환산 |
|---|---|---:|---:|
| OpenAI | `whisper-1` | $0.006 / 분 | $0.006 |
| Groq | `whisper-large-v3-turbo` | $0.04 / 시간 | 약 $0.000667 |

하루 4~5시간 업로드 기준 추정은 아래와 같습니다. 5분 샘플에서 VAD + 1.25배속으로 길이가 27.4% 줄었던 비율을 하루 약 4.1시간($1.48 분량)에 적용했습니다.

| 항목 | 최적화 전 | 최적화 후 |
|---|---:|---:|
| 원본 오디오 | 약 246분 (4.1시간) | 약 246분 (4.1시간) |
| Whisper 제출 길이 | 246분 | 약 179분 |
| STT Provider | OpenAI | Groq |
| 추정 STT 비용 | 약 $1.48 | 약 $0.11~$0.12 |

179 x ($0.04 / 60) = 약 $0.12로, 표의 $0.11과 같은 자리입니다.

이 추정치는 유료 Groq 단가 기준입니다. 사용 중인 건 무료 플랜이므로 STT 자체는 더 싸고, 남는 비용은 검색용 임베딩(`text-embedding-3-small`)뿐입니다. 임베딩은 STT provider와 분리되어 있어 Groq로 STT를 바꿔도 검색용 OpenAI 키는 따로 씁니다.

현재 Class S 기본 파이프라인은 VAD + 1.25배속 + Groq `whisper-large-v3-turbo`입니다. 하루 4~5시간 업로드 기준 STT 비용 부담을 실사용 가능한 수준까지 낮춘 상태입니다.
