    • 영상 업로드부터 비동기 인코딩과 콘텐츠 배포까지 이어지는 처리 파이프라인 설계와 운영
    • Presigned URL을 이용한 S3 직접 업로드와 PublishJob 생성
    • AWS SQS 작업 전달, FFmpeg HLS 인코딩, S3와 CloudFront 배포 구조 구현
    • 의료 데이터의 수집, 처리, 저장, 제공 전 과정을 개발하고 데이터 특성에 따라 파일 시스템과 데이터베이스 저장 방식을 구분
    • 프록시 네트워크와 요청 최적화를 활용해 수십만~100만 건 규모의 이커머스 상품 데이터 수집
    • 의료 데이터 암호화 및 기존 데이터를 신규 테이블 구조로 이전하는 마이그레이션 수행

  3. 서비스 안정성 및 운영 자동화

    • AWS EC2, S3, CloudFront, CloudWatch 환경에서 서비스 배포, 모니터링, 장애 대응 경험
    • 특정 기간에 트래픽이 집중되는 일일 참여자 10만 명 이상 규모의 이벤트 서비스를 운영하고 실시간 장애에 대응
    • Celery 작업 재시도와 실행 제한 시간으로 발생한 작업 상태 불일치 문제를 분석하고 작업 처리 설정과 상태 관리 로직 개선
    • 로깅 시스템과 에러 처리 방식을 개선하고 핵심 데이터 처리 로직의 단위 테스트를 추가
    • GitHub Actions와 ECR을 활용해 Docker 이미지 빌드와 배포 과정을 자동화하고 서버 내부의 수동 빌드 작업을 개선

  4. 성능 최적화 및 점진적 아키텍처 개선

    • Go의 동시성 모델을 활용해 의료 이미지 처리 로직을 병렬화하고 처리 시간을 약 11초에서 4초로 단축
    • 의료기기 통신 과정에 로컬 캐싱 구조를 도입해 DB 접근량을 기존 대비 22% 절감
    • 기존 서비스에 미치는 영향을 최소화하면서 도메인별 책임과 의존성을 분리하는 방향으로 레거시 구조 개선
    • API 서버와 영상 인코딩 워커의 역할을 분리하고 작업 큐 기반으로 확장할 수 있는 처리 구조 설계
    • FFmpeg의 코덱, CRF, 비트레이트, 프레임 레이트 옵션을 분석하고 조정해 영상 품질과 HLS 재생 안정성 개선

  5. RAG 및 LLM 기반 검색 시스템 설계

    • 강의 자막과 메타데이터를 청킹하고 임베딩하여 LLM이 활용할 수 있는 검색 인덱싱 파이프라인 구축
    • PostgreSQL FTS와 pgvector를 결합한 키워드, 의미 기반 하이브리드 검색 구현
    • 검색 품질이 낮은 경우 LLM Query Rewrite 후 재검색하는 조건부 검색 최적화 로직 구현
    • 검색 결과를 기반으로 실 데이터와 교차 검증을 적용해 근거 없는 응답과 Hallucination 방지
    • Golden Dataset 기반 RAG 회귀 테스트와 검색 랭킹 A/B 테스트 구조를 구축해 품질을 지속적으로 검증 가능한 구조 설계

프로젝트

Lecture Streaming Service (개인) 2026.05 - 현재

동영상 도메인으로 역량을 확장하기 위해 구현한 프로젝트입니다.

단순히 영상을 업로드하는 기능이 아니라, 업로드된 영상을 비동기로 처리하고 HLS로 변환한 뒤 S3와 CloudFront를 통해 제공하는 구조입니다.

주요 기능

  • User: 회원가입 및 로그인 / 업로더 권한 승인
  • Media: 커리큘럼 관리 / 강좌 관리 / 강의 타임라인 관리 / 영상 업로드 / HLS 인코딩 결과 배포
  • Job: 영상 시청 플로우 / 영상 Publish 작업 관리
  • QnA: 자유 QnA / 마크다운 입력 지원 (QnA/댓글)
  • AI: 썸네일 생성 페이지에서 이미지 및 썸네일 생성

데이터 플로우

Client → Backend API (init) → Presigned URL
→ Client S3 Direct PUT → commit → PublishJob → SQS
→ CloudWatch / ASG 워커 → FFmpeg HLS 인코딩 → S3 저장
→ CloudFront 배포 → Client 재생
